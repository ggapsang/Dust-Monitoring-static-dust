# `/config` 파라미터 해설

판독 서비스가 지금 어떤 값으로 돌고 있는지 보여주는 API 다.

```
GET http://localhost:8911/config
```

이 문서는 그 응답에 들어 있는 값 하나하나가 **무엇을 하는 값이고, 올리거나
내리면 판독 결과가 어떻게 달라지는지**를 설명한다. 영상처리를 모르는 사람도
읽고 값을 조정할 수 있게 쓰였다.

---

## 응답 형태

```json
{
  "source": "/app/config/default.yaml",
  "values": { "spec": "v2", "pad_size_px": 1120, ... }
}
```

| 키 | 뜻 |
|---|---|
| `source` | 이 값들을 **어느 파일에서 읽었는지**. 설정 파일을 바꿨는데 결과가 그대로라면 여기부터 확인한다. 경로가 예상과 다르면 엉뚱한 파일을 읽고 있는 것이다. `null` 이면 파일을 못 찾아 코드에 내장된 기본값으로 돌고 있다는 뜻이다. |
| `values` | 실제 적용 중인 설정 전량. 아래에서 항목별로 설명한다. |

## 읽기 전에 알아야 할 두 가지

**하나. `null` 은 "그 검사를 하지 않는다" 는 뜻이다.**

임계값이 `null` 이면 그 항목으로 이미지를 거르지 않는다. 다만 **측정 자체는
항상 한다.** 즉 `max_tilt_deg` 가 `null` 이어도 판독 결과에는 추정 촬영 각도가
들어 있다. 그래서 순서가 이렇게 된다.

1. 임계값을 비워 둔 채로 현장 사진을 잔뜩 판독한다
2. 결과에 실려 나온 측정값들의 분포를 본다
3. "이 정도면 못 쓰겠다" 싶은 선을 임계값으로 넣는다

거꾸로 임계값을 먼저 짐작해서 넣으면, 멀쩡한 사진이 걸러지고 있는지 아닌지
알 방법이 없다.

**둘. `/config` 는 읽기 전용이다.**

값을 바꾸려면 두 가지 방법이 있다.

- **영구적으로**: `config/default.yaml` 을 고치고 서비스를 재시작한다
- **이번 요청만**: `/read` 를 부를 때 `config` 필드에 바꿀 부분만 얹는다.
  서버 설정은 그대로 남는다. 임계값을 이리저리 시험해 볼 때 쓴다

```bash
curl -F "file=@pad.png" -F 'config={"grid":{"rows":4,"cols":4}}' \
     "localhost:8911/read?tone=white"
```

없는 항목 이름을 쓰면 400 으로 튕긴다. 오타 난 설정이 조용히 무시되면 그게
적용된 줄 알고 판독하게 되기 때문이다.

# 최상위

## `spec` — 기본값 `"v2"`

**어느 도안의 패드를 읽을 것인가.**

패드에는 테두리, 모서리 블록, 번호, 아래쪽 선들이 정해진 자리에 인쇄되어
있다. 판독기는 "여기에 뭐가 있을 것" 이라는 지도를 들고 이미지를 읽는데,
그 지도의 이름이 `spec` 이다. **실제로 부착한 패드와 다른 이름을 넣으면
엉뚱한 자리를 재게 되므로 반드시 맞춰야 한다.**

| 값 | 언제 쓰나 |
|---|---|
| `legacy` | 최초 샘플 도안 그대로 만든 패드 |
| `v2` | 현행 권장 도안 |
| `v2_protected` | v2 인데 기준 패치를 라미네이트·투명창으로 **덮어서** 만든 패드 |

`v2_protected` 는 물리적으로 덮은 패드에만 쓴다. 덮지 않았는데 이 이름을
쓰면 분진 신호가 사라져 항상 "깨끗함" 으로 읽힌다.

## `pad_size_px` — 기본값 `1120`

**비스듬히 찍힌 패드를 정면으로 펴서 몇 픽셀짜리 정사각형으로 만들 것인가.**

촬영 각도와 거리가 매번 다르기 때문에, 판독 전에 사진 속 패드를 "정면에서
반듯하게 본 모습" 으로 변환한다. 그 결과물의 한 변 길이다.

- **올리면**: 더 세밀하게 보지만 처리 시간이 늘어난다. 원본에 없는 해상도가
  생기지는 않으므로, 원본이 흐리면 키워도 소용없다
- **내리면**: 빨라지지만 미세한 얼룩을 놓칠 수 있다

기본값은 실제 촬영 크기와 비슷하게 잡은 것이다. 특별한 이유가 없으면 건드리지
않는다.

## `pad_size_mm` — 기본값 `null`

**패드 한 변의 실제 길이(mm).**

이 값을 채우면 "픽셀 몇 개가 몇 mm 인지" 를 알 수 있어, 나중에 오염 면적을
mm² 단위로 환산할 수 있다. 아직 패드 실물 치수가 확정되지 않아 비워 두었다.
비워 둬도 분진 스코어 산출에는 영향이 없다.

# `detect` — 사진에서 패드 찾기

가장 먼저 하는 일은 "사진 어디에 패드가 있는가" 를 찾는 것이다. 패드의 굵은
검은 테두리를 단서로 삼는다.

## `blur_ksize` — 기본값 `5`

**패드를 찾기 전에 이미지를 얼마나 뿌옇게 만들 것인가.**

사진에는 자잘한 노이즈(모래알 같은 얼룩)가 있어서, 그대로 두면 테두리 선이
울퉁불퉁하게 잡힌다. 살짝 뿌옇게 만들면 노이즈가 뭉개져 테두리가 매끈해진다.
숫자는 뿌옇게 만드는 붓의 굵기라고 보면 된다.

- **올리면**: 노이즈에 강해지지만 너무 키우면 테두리 자체가 뭉개져 못 찾는다
- **`0`**: 뿌옇게 만들지 않는다. 아주 깨끗한 이미지에서만

> 이 값은 **패드를 찾는 데만** 쓴다. 분진을 재는 단계에서는 뿌옇게 만들지
> 않은 원본을 쓰므로, 이 값을 올려도 측정값이 뭉개지지는 않는다.

## `min_pad_area_ratio` / `max_pad_area_ratio` — 기본값 `0.005` / `0.98`

**사진 전체 넓이 대비, 패드가 차지할 만한 넓이의 하한과 상한.**

사진에는 패드 말고도 사각형처럼 생긴 것들이 찍힌다. 넓이로 먼저 걸러낸다.
`0.005` 는 사진 넓이의 0.5%, `0.98` 은 98% 다.

- **하한을 올리면**: 멀리서 작게 찍힌 패드를 못 찾게 된다
- **상한을 내리면**: 아주 가까이서 화면 가득 찍은 패드를 못 찾게 된다

AMR 이 항상 비슷한 거리에서 찍는다면 범위를 좁혀 오검출을 줄일 수 있다.

## `approx_epsilon_ratio` — 기본값 `0.02`

**찾아낸 윤곽선을 "네모" 로 볼 때 얼마나 대충 볼 것인가.**

카메라로 찍은 테두리는 완벽한 직선이 아니라 미세하게 구불거린다. 그 구불거림을
어느 정도까지 무시하고 "이건 사각형이다" 라고 판단할지의 관용도다. 테두리
둘레 길이의 몇 배까지 봐줄지로 표현한다.

- **올리면**: 구불구불한 것도 사각형으로 인정한다. 오검출이 는다
- **내리면**: 조금만 휘어도 사각형으로 안 본다. 패드를 놓칠 수 있다

## `require_ring` — 기본값 `true`

**"가운데가 뚫린 사각형" 만 패드로 인정할 것인가.**

패드의 테두리는 속이 빈 액자 모양이다. 반면 현장에 널린 사각형 물체(표지판,
상자 등)는 대개 속이 꽉 차 있다. 이 조건 하나로 오검출이 크게 준다.

- **`true`**: 액자 모양만 인정 (권장)
- **`false`**: 테두리 일부가 사진 밖으로 잘려나가 액자가 끊긴 경우에만 끈다.
  대신 엉뚱한 사각형을 패드로 착각할 위험이 커진다

## `min_solidity` — 기본값 `0.85`

**찾은 모양이 얼마나 "빈틈없이 채워진" 모양인가.**

찾아낸 윤곽을 고무줄로 감쌌다고 상상했을 때, 고무줄 안쪽이 얼마나 채워져
있는지의 비율이다. 반듯한 사각형은 1 에 가깝고, 별 모양이나 갈라진 모양은
작다.

- **올리면**: 반듯한 것만 인정. 테두리가 조금 가려진 패드를 놓칠 수 있다
- **내리면**: 찌그러진 모양도 인정. 오검출이 는다

## `max_aspect_ratio` — 기본값 `3.0`

**가로세로 비율이 얼마나 찌그러진 것까지 패드로 볼 것인가.**

패드는 정사각형이지만 비스듬히 찍으면 사다리꼴로 찌그러진다. `3.0` 은 가장 긴
변이 가장 짧은 변의 3배까지는 봐준다는 뜻이다.

- **내리면**: 정면에 가까운 사진만 받는다
- **올리면**: 극단적으로 눕혀 찍은 사진도 시도한다. 다만 그렇게 찍은 사진은
  어차피 측정 정밀도가 떨어진다

## `edge_trim_ratio` — 기본값 `0.15`

**테두리 각 변을 잴 때 양 끝을 얼마나 버릴 것인가.**

패드의 네 꼭짓점을 아주 정밀하게 찾기 위해, 판독기는 꼭짓점을 직접 보지 않고
**네 변에 직선을 맞춘 뒤 그 교점**을 꼭짓점으로 삼는다. 인쇄된 모서리는
둥글게 뭉개져 있어서 그대로 보면 부정확하기 때문이다.

이 값은 각 변의 양 끝에서 몇 %를 버릴지다. `0.15` 면 변의 앞 15%와 뒤 15%를
버리고 가운데 70%만 쓴다.

- **올리면**: 모서리 영향은 확실히 피하지만 직선을 맞출 재료가 줄어든다
- **내리면**: 뭉개진 모서리가 섞여 들어와 꼭짓점 위치가 흔들린다

# `orient` — 패드가 어느 방향으로 붙어 있나

패드 네 모서리 중 **세 곳에만** 검은 사각형이 인쇄되어 있다. 비어 있는 한
곳이 어디인지를 보면 패드가 어느 방향으로 붙었는지 알 수 있다.

## `min_margin` — 기본값 `null`

**방향 판정을 얼마나 확신할 때만 받아들일 것인가.** (0 ~ 1)

네 모서리를 재서 "가장 비어 보이는 곳" 과 "그 다음으로 비어 보이는 곳" 의
차이를 본다. 이 차이가 크면 확실한 것이고, 작으면 헷갈리는 상태다.

- `1` 에 가까움: 한 곳만 확실히 비었다 — 판정 확실
- `0` 에 가까움: 네 곳이 비슷비슷하다 — 어느 쪽인지 모르겠다

`null` 이면 아무리 헷갈려도 일단 판정하고 넘어간다. 값을 넣으면 그 미만일 때
판독 불가로 되돌린다. 방향을 잘못 잡으면 좌표계 전체가 90도 틀어져 엉뚱한
곳을 재게 되므로, 실제 사진의 분포를 본 뒤 넉넉하게 걸어 두는 것이 좋다.

# `quality` — 이 사진, 믿고 읽어도 되나

측정하기 전에 사진 자체가 쓸 만한지 검사한다. **모든 값이 기본적으로 `null`
(검사 안 함)** 이며, 측정값은 임계값과 무관하게 항상 결과에 실려 나온다.

## `max_edge_rise_ratio` — 기본값 `null`

**얼마나 흐린 사진까지 받아들일 것인가.** (작을수록 선명)

초점이 맞은 사진은 테두리의 검은색과 흰색이 한두 픽셀 만에 확 바뀐다. 흐린
사진은 그 변화가 여러 픽셀에 걸쳐 서서히 일어난다. 이 값은 **"흑백이 바뀌는
데 걸리는 거리가 패드 폭의 몇 %인가"** 다.

패드 폭으로 나누기 때문에 **멀리서 찍든 가까이서 찍든 같은 기준으로 비교된다.**
가까이서 찍으면 당연히 픽셀이 많아지는데, 그걸 "더 선명하다" 고 오판하지
않는다.

참고로 합성 실험에서 나온 값이다.

| 상태 | 값 |
|---|---|
| 초점이 잘 맞음 | 약 0.002 |
| 약간 흔들림 | 약 0.005 |
| 뚜렷하게 흐림 | 약 0.022 |

- **낮게 걸면**: 아주 선명한 사진만 받는다. 판독 불가가 늘어난다
- **높게 걸면**: 흐린 사진도 읽는다. 미세한 얼룩을 놓칠 수 있다

## `min_tenengrad` — 기본값 `null`

**선명도를 재는 또 다른 방식.** (클수록 선명)

테두리 부분에서 밝기가 얼마나 급격하게 변하는지를 합산한 값이다.
`max_edge_rise_ratio` 와 같은 것을 다른 방식으로 재는 셈인데, 이쪽은 **잉크
농도나 조명 세기에 따라 값이 같이 변한다**는 약점이 있다.

두 지표를 모두 내보내는 이유는, 실제 현장 사진에서 어느 쪽이 "판독 실패" 와
더 잘 맞아떨어지는지 아직 모르기 때문이다. 실증 데이터를 보고 하나를 고르면
된다. 둘 다 걸어도 되지만 보통은 하나면 충분하다.

## `max_saturated_bright_ratio` / `max_saturated_dark_ratio` — 기본값 `null`

**너무 밝아서 하얗게 날아갔거나, 너무 어두워서 새까맣게 뭉갠 픽셀의 비율.**

카메라는 밝기를 0~255 로 기록한다. 255 를 넘는 밝기는 전부 255 로 기록되므로,
**그보다 밝았는지 훨씬 밝았는지 구분할 수 없다.** 정보가 잘려나간 것이다.
0 쪽도 마찬가지다.

이런 픽셀이 많으면 측정이 무너진다. 특히 밝은 쪽이 날아가면 기준으로 쓰는
흰색 패치까지 잘려서 밝기 환산 자체가 어긋난다.

- 값은 비율이다. `0.01` 이면 "패드 면적의 1%까지만 허용"
- 조명이 세거나 노출이 과하면 밝은 쪽이, 어두운 곳에서 찍으면 어두운 쪽이 는다
- 정상 사진에서는 보통 `0.0` 이다

## `max_tilt_deg` — 기본값 `null`

**얼마나 비스듬히 찍은 사진까지 받아들일 것인가.** (단위: 도)

정면에서 찍으면 패드가 정사각형으로 보이고, 비스듬히 찍으면 사다리꼴로
찌그러진다. 그 찌그러진 정도를 각도로 환산한 값이다.

카메라 렌즈 정보 없이 사진 하나만으로 추정하는 값이라 **정확한 각도라기보다는
"얼마나 비스듬한가" 의 눈금**으로 쓴다. 정면에 가까울수록 0 에 가깝다.

- **낮게 걸면**: 정면에 가까운 사진만 받는다. 측정은 안정되지만 재촬영이 는다
- 정면 보정으로 각도를 어느 정도 상쇄하므로, 무조건 낮게 걸 필요는 없다

## `min_pad_size_px` — 기본값 `null`

**사진 속 패드가 최소 몇 픽셀은 되어야 하는가.**

너무 멀리서 찍어 패드가 작게 나오면, 아무리 잘 보정해도 원본에 없는 정보가
생기지는 않는다. 이럴 때 걸러낸다.

- 값은 "패드 한 변에 해당하는 픽셀 수" 다. `400` 이면 패드가 400×400 픽셀
  이상으로 찍혀야 한다는 뜻
- AMR 의 정차 위치가 일정하다면 실제 값도 일정하게 나오므로, 현장 분포를
  보고 그보다 조금 낮게 잡으면 된다

## `min_anchor_contrast` — 기본값 `null`

**밝기 환산의 기준이 되는 두 지점의 밝기 차이가 최소 얼마여야 하는가.**

판독기는 패드에 인쇄된 **검은 기준점과 흰 기준점**을 자로 삼아 "이 밝기는
반사율 얼마" 를 환산한다. 두 기준점의 밝기 차이가 그 자의 눈금 폭이다.

조명이 너무 어둡거나 사진이 심하게 흐리면 이 차이가 좁아진다. 눈금이 좁은
자로 재면 오차가 그대로 확대되므로, 일정 이하면 아예 읽지 않는 편이 낫다.

- 값은 0~255 밝기 단위다. 정상적인 사진에서는 150~250 정도가 나온다
- 앵커가 없는 도안에서는 테두리와 여백의 밝기 차이로 대신한다

## `saturation_bright_level` / `saturation_dark_level` — 기본값 `250` / `5`

**밝기 몇부터를 "날아갔다", 몇 이하를 "뭉갰다" 로 볼 것인가.**

위의 포화 비율을 셀 때 쓰는 경계선이다. 0~255 밝기 값 기준으로 `250` 이상이면
밝은 쪽 포화, `5` 이하면 어두운 쪽 포화로 센다.

이론상 255 와 0 이 진짜 포화지만, 실제 카메라는 그 직전부터 이미 밝기 구분이
무뎌지므로 조금 여유를 두었다. **이건 임계값이 아니라 세는 방식의 정의**라
`null` 로 둘 수 없다.

# `normalize` — 조명 차이 지우기

같은 패드라도 형광등 아래와 그늘에서 찍으면 밝기가 다르게 나온다. 그 차이를
지우고 **패드 표면 자체의 밝기(반사율)** 만 남기는 단계다. 이게 안 되면 분진이
쌓인 건지 조명이 어두운 건지 구분할 수 없다.

## `method` — 기본값 `"auto"`

**무엇을 밝기의 기준자로 삼을 것인가.**

| 값 | 방식 |
|---|---|
| `auto` | 패드에 보호된 기준 패치가 있으면 `two_point`, 없으면 `border_ratio` |
| `two_point` | 패드에 인쇄된 **검은 패치와 흰 패치 두 곳**을 자의 양 끝으로 쓴다 |
| `border_ratio` | 검은 **테두리 한 곳**만 기준으로 쓴다 |

`two_point` 가 원리적으로 훨씬 낫다. 카메라는 완전한 검은색을 찍어도 0 이
아니라 약간 뜬 값을 기록하는데(센서가 더하는 바닥값), 기준이 두 개면 그
바닥값까지 함께 상쇄된다. 기준이 하나면 상쇄되지 않는다.

**다만 기준 패치가 물리적으로 덮여 있어야 한다.** 덮이지 않으면 기준 패치에도
분진이 똑같이 쌓여서, 측정하려는 신호가 기준과 함께 움직여 상쇄되어 사라진다.
그래서 `auto` 는 도안이 "보호됨" 이라고 선언한 경우에만 `two_point` 를 고른다.

`border_ratio` 는 **흰 바탕 패드에서 특히 부정확하다.** 기준이 되는 검은
잉크가 워낙 어두워서 센서 바닥값의 비중이 커지기 때문이다. 값이 커질수록
오염이 심한 것은 맞지만(순서는 보존된다), 절대 수치는 믿기 어렵다.

## `gradient_correction` — 기본값 `"border"`

**조명이 한쪽에서만 비칠 때 생기는 밝기 기울기를 어떻게 지울 것인가.**

옆에서 빛이 들면 깨끗한 패드인데도 한쪽이 밝고 반대쪽이 어둡게 찍힌다. 이걸
그대로 두면 어두운 쪽이 "오염된 것" 으로 오판된다.

| 값 | 방식 |
|---|---|
| `border` | **테두리**의 밝기가 위치에 따라 어떻게 변하는지 보고 그만큼 되돌린다 (권장) |
| `none` | 보정하지 않는다 |
| `margin` | 측정 영역 자체의 밝기 기울기를 보고 되돌린다 |

테두리를 쓰는 이유는 **테두리의 원래 밝기가 어디나 같다는 것을 알기 때문**이다.
그런데도 위치에 따라 밝기가 다르게 찍혔다면 그건 순전히 조명 탓이다.

`margin` 은 위험하다. 분진이 전체적으로 고르게 쌓이면 그것까지 "조명 기울기"
로 오해해서 지워 버린다. 즉 진짜 신호를 지운다.

## `ring_samples` — 기본값 `600`

**조명 기울기를 계산할 때 테두리에서 몇 군데를 재 볼 것인가.**

기울기를 구하려면 최소 3점이면 되지만, 그렇게 하면 **결과가 맞는지 틀린지
알 방법이 없다.** 표본이 딱 필요한 만큼이면 어떤 값이든 완벽하게 들어맞아
버리기 때문이다.

600 군데를 재면 "이 기울기 추정이 실제 데이터와 얼마나 어긋나는지" 가 숫자로
나온다. 판독 결과의 `plane_residual_rms` 가 그 값이며, 크면 조명 추정을 믿기
어렵다는 뜻이다.

- **올리면**: 추정이 안정되고 신뢰도 지표가 정확해진다. 조금 느려진다
- **내리면**: 빨라지지만 노이즈에 흔들리고 신뢰도를 판정하기 어려워진다

## `assumed_ink_reflectance_dark` / `assumed_ink_reflectance_light` — 기본값 `0.06` / `0.88`

**인쇄된 검은색과 흰색이 실제로 빛을 몇 % 반사하는가.** (0~1)

`border_ratio` 방식에서만 쓴다. 기준이 테두리 하나뿐이라, "이 테두리가 원래
반사율 6% 짜리 검정" 이라고 **가정해야** 나머지 밝기를 반사율로 환산할 수 있다.

- `dark` = 흰 바탕 패드에 인쇄된 **검은 잉크** (무광 검정은 대략 5~7%)
- `light` = 검은 바탕 패드에 인쇄된 **흰 잉크** (백색 인쇄는 대략 85~90%)

실제 인쇄물의 반사율을 측정해서 넣으면 정확도가 올라간다. `two_point` 방식을
쓰면 가정이 필요 없어지므로 이 값은 무시된다.

# `grid` — 측정 영역을 몇 칸으로 나눌 것인가

패드 가운데의 빈 영역을 격자로 나눠 칸마다 따로 잰다. 칸별로 재야 **"전체가
고르게 더러워졌는지" 와 "한 곳만 뭉쳐 있는지"** 를 구분할 수 있다.

## `rows` / `cols` — 기본값 `8` / `11`

**세로 몇 칸, 가로 몇 칸으로 나눌 것인가.**

측정 영역이 가로로 긴 직사각형이라 행과 열을 따로 둔다. 기본값 8×11 = 88칸은
각 칸이 거의 정사각형이 되도록 잡은 것이다.

- **잘게 나누면**(예: 16×22): 작은 얼룩도 한 칸을 확실히 채워 눈에 띈다.
  대신 칸마다 픽셀 수가 줄어 값이 노이즈에 흔들린다
- **크게 나누면**(예: 4×4): 값이 안정되지만 작은 얼룩이 큰 칸 안에서 희석된다

찾으려는 얼룩의 크기에 맞추는 것이 요령이다. 칸이 얼룩보다 훨씬 크면 놓치고,
훨씬 작으면 노이즈만 늘어난다.

## `min_valid_pixel_ratio` — 기본값 `0.9`

**한 칸에서 쓸 수 있는 픽셀이 최소 몇 %는 되어야 그 칸을 인정할 것인가.**

측정 영역에는 원래 인쇄물이 없도록 도안이 잡혀 있어서, 보통 모든 칸이 100%
쓸 수 있다. 이 검사는 **도안이 바뀌어 인쇄물이 측정 영역으로 들어왔을 때를
대비한 안전장치**다.

그런 칸은 인쇄된 검은 선이 섞여 "심하게 오염됨" 으로 잘못 읽히므로, 조용히
틀린 값을 내는 대신 아예 제외한다. 제외된 칸은 결과에서 `masked` 로 표시된다.

# `exclude` — 분진이 아닌 것 걸러내기

패드에 앉는 것이 분진만은 아니다. 녹물, 기름때, 결로 자국도 표면을 더럽힌다.
이런 것까지 분진으로 세면 안 된다.

## `chroma_metric` — 기본값 `"norm"`

**"색이 있는가" 를 어떤 방식으로 잴 것인가.**

분진은 무채색(검정 또는 흰색)이다. 반면 녹은 붉고 기름때는 누렇다. **색이
있으면 분진이 아니다** 라는 것이 판단 근거다.

| 값 | 방식 | 성질 |
|---|---|---|
| `norm` | 색의 진하기를 **조명 밝기로 나눈** 값 | 조명이 밝든 어둡든 같은 값 |
| `abs` | 색의 진하기 그대로 | 밝게 찍히면 커지고 어둡게 찍히면 작아짐 |

`norm` 이 기본값인 이유는 조명이 바뀌어도 임계값을 다시 잡지 않아도 되기
때문이다. 두 값 모두 판독 결과에 실려 나오므로, 실제 녹·기름때 사진을 모아
어느 쪽이 더 잘 갈라지는지 보고 정하면 된다.

> 참고로 영상처리에서 흔히 쓰는 HSV 의 채도(S)는 여기에 쓰면 안 된다.
> 그 방식은 **어두운 픽셀에서 값이 폭주**해서, 측정 영역 전체가 어두운
> 검은 바탕 패드에서는 모든 칸이 "색이 있다" 로 판정되어 버린다.

## `max_chroma` — 기본값 `null`

**색이 얼마나 진하면 분진이 아니라고 볼 것인가.**

이 값을 넘는 칸은 `chroma` 사유로 측정에서 제외된다. 몇 칸이 어떤 사유로
빠졌는지는 판독 결과에 함께 나온다.

- **낮게 걸면**: 조금만 색이 돌아도 제외한다. 실제 분진까지 버릴 수 있다
- **높게 걸면**: 녹이나 기름때를 분진으로 세게 된다
- `null` 이면 색으로는 걸러내지 않는다

## `max_saturated_ratio` — 기본값 `null`

**한 칸 안에서 밝기가 날아간 픽셀이 몇 %를 넘으면 그 칸을 버릴 것인가.**

패드 표면에 조명이 정면으로 반사되면(정반사, 흔히 말하는 "번쩍임") 그 부분이
새하얗게 날아간다. 그 칸은 표면 상태를 알 수 없으므로 제외한다.

- **낮게 걸면**: 조금만 번쩍여도 그 칸을 버린다. 쓸 수 있는 칸이 줄어든다
- **높게 걸면**: 번쩍인 칸이 "아주 밝음 = 깨끗함" 으로 잘못 읽힌다

`null` 이면 이 검사를 하지 않는다. 다만 칸 안의 포화 픽셀 비율 자체는 항상
결과에 나오므로, 현장 사진에서 실제로 번쩍임이 얼마나 생기는지 보고 정하면 된다.

# `score` — 칸별 값을 하나의 점수로

## `statistic` — 기본값 `"p90"`

**88개 칸의 값 중 무엇을 대표값으로 삼을 것인가.**

| 값 | 뜻 |
|---|---|
| `max` | 가장 심한 칸의 값 |
| `p90` | 위에서 10% 지점의 값 (기본값) |
| `p75`, `p50` … | `p` 뒤의 숫자가 분위수. `p50` 은 중앙값 |

**평균은 의도적으로 지원하지 않는다.** 한 곳에서 분진이 새어 두세 칸만 심하게
더러워졌다고 하자. 평균을 쓰면 나머지 깨끗한 85칸에 희석되어 거의 변화가
없어 보인다. 국소 누출을 잡는 것이 목적인데 그걸 못 잡게 된다.

- `max` 는 가장 민감하지만 **노이즈나 이물 하나에도 크게 흔들린다**
- `p90` 은 상위 몇 칸을 보되 최고값 하나에 휘둘리지 않는 절충안
- 낮은 분위수로 갈수록 "전체적으로 얼마나 더러운가" 에 가까워진다

칸 수가 적으면(예: 4×4 = 16칸) `p90` 이 사실상 최고값에 가까워지므로, 격자를
크게 바꿀 때는 이 값도 같이 검토한다.

# `lines` — 보조 지표

## `enabled` — 기본값 `true`

**패드 아래쪽의 굵기가 다른 4개 선을 측정할 것인가.**

패드 하단에는 굵기가 두 배씩 차이 나는 선 4개가 인쇄되어 있다. 얇은 선일수록
분진이나 흐림에 먼저 묻혀 사라진다.

이 항목은 **"빈 영역을 재는 방식" 과 "선이 묻히는 정도를 보는 방식" 중 어느
쪽이 미세한 오염에 먼저 반응하는가** 를 같은 사진에서 비교하기 위한 실증용
지표다. 상시 운용 지표가 아니므로, 비교가 끝나면 꺼서 처리 시간을 줄여도 된다.

결과에는 단계별로 `contrast` 가 나온다. `1` 이면 선이 또렷하고 `0` 이면 여백과
구분되지 않는다는 뜻이다.

# `target_id` — 패드에 인쇄된 관측 포인트 번호 읽기

## `enabled` — 기본값 `true`

**번호를 읽을 것인가.**

패드마다 관측 포인트 번호가 인쇄되어 있어, 사진 한 장만으로 "이게 어느 지점의
패드인지" 를 알 수 있다. 촬영 위치가 다른 경로로 확실히 관리된다면 꺼서 처리
시간을 줄여도 된다.

> 번호를 못 읽어도 **판독 실패가 아니다.** 패드 자체는 읽혔고 분진 스코어는
> 그대로 유효하다. 결과의 `target_id_status` 에 `failed` 로 표시될 뿐이다.

## `min_confidence` — 기본값 `0.55`

**얼마나 확신할 때만 읽은 번호를 믿을 것인가.** (0 ~ 1)

번호 판독은 학습 모델이 아니라 **우리가 인쇄한 것과 같은 모양의 숫자를 다시
그려서 겹쳐 보는 방식**이다. 얼마나 잘 겹치는지가 그대로 확신도가 된다.

여러 자리 중 **가장 안 겹친 자리**의 점수를 확신도로 쓴다. 한 자리만 틀려도
번호 전체가 틀리기 때문에 평균을 내면 안 된다.

- **올리면**: 확실할 때만 읽는다. 못 읽었다고 나오는 경우가 는다
- **내리면**: 틀린 번호를 맞다고 내놓을 수 있다

## `digits` — 기본값 `null`

**번호가 몇 자리인지.**

- `null`: 검출된 만큼 읽는다
- 숫자(예: `4`): 정확히 그 자릿수가 검출될 때만 읽는다

관측 포인트 번호 자릿수가 전부 같다면 값을 넣어 두는 편이 안전하다. 얼룩을
숫자로 착각해 다섯 자리로 읽는 것 같은 사고를 막아 준다.

# `service` — 서비스 기동 설정

판독 결과에는 영향이 없다. **바꾸려면 서비스를 재시작해야 한다.**

## `host` — 기본값 `"0.0.0.0"`

**어느 네트워크 주소에서 요청을 받을 것인가.**

- `0.0.0.0`: 모든 네트워크에서 접속 허용 (컨테이너에서는 이 값이어야 한다)
- `127.0.0.1`: 같은 장비에서만 접속 허용

## `port` — 기본값 `8911`

**몇 번 포트로 서비스할 것인가.**

컨테이너로 띄운 경우 이 값만 바꿔서는 바깥에서 접속되지 않는다.
`docker-compose.yml` 의 포트 연결도 함께 맞춰야 한다.

# 임계값을 처음 정하는 순서

1. **임계값을 전부 `null` 로 둔 채** 현장 사진을 최대한 많이 판독한다
2. 결과 CSV 에서 각 측정값의 분포를 본다

   ```bash
   python -m padtools.batch <사진폴더> --tone white --csv result.csv
   ```

   최소·중앙·최대가 요약되어 나온다
3. 사람 눈으로 "이건 못 쓰겠다" 싶은 사진을 몇 장 골라, 그 사진들의 측정값이
   정상 사진과 어디서 갈라지는지 찾는다
4. 그 경계를 임계값으로 넣고 다시 돌려, 의도한 사진만 걸러지는지 확인한다

한 번에 여러 임계값을 넣지 않는 것이 요령이다. 무엇 때문에 걸렸는지 알 수
없게 된다. 판독 불가로 반환될 때는 **어느 항목에서 걸렸는지**가 결과에 함께
나오므로 그것을 보고 하나씩 조정한다.
