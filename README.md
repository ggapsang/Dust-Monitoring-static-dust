# `/config` 파라미터 해설

판독 서비스가 지금 어떤 값으로 돌고 있는지 보여주는 API 다.

    GET http://localhost:8911/config

응답의 `source` 는 이 값들을 어느 파일에서 읽었는지다. 설정을 고쳤는데 결과가
그대로면 여기부터 본다. `null` 이면 파일을 못 찾아 코드에 내장된 기본값으로
돌고 있다는 뜻이다. `values` 가 실제 적용 중인 설정이며 아래에서 하나씩
설명한다.

## 읽기 전에

- **`null` 은 "그 검사를 하지 않는다" 는 뜻이다.** 임계값이 비어 있어도 측정
  자체는 항상 하고, 그 값은 판독 결과에 실려 나온다. 그래서 순서가 이렇다 —
  임계값을 비운 채로 현장 사진을 잔뜩 판독하고, 결과에 나온 측정값의 분포를
  보고, "이 정도면 못 쓰겠다" 싶은 선을 넣는다. 거꾸로 임계값을 먼저 짐작해
  넣으면 멀쩡한 사진이 걸러지고 있는지 알 방법이 없다.
- **`/config` 는 읽기 전용이다.** 영구히 바꾸려면 `config/default.yaml` 을
  고치고 서비스를 재시작한다. 이번 요청에만 적용하려면 `/read` 의 `config`
  칸에 바꿀 부분만 얹는다. 없는 항목 이름을 쓰면 400 으로 튕긴다 — 오타 난
  설정이 조용히 무시되면 그게 적용된 줄 알고 판독하게 된다.

      curl -F "file=@pad.jpg" -F "baseline=@clean.jpg" -F "tone=white" \
           -F 'config={"dust":{"depth_threshold":0.08}}' \
           localhost:8911/read

## 파라미터

- **`spec`** · `legacy` — 판독기가 들고 보는 지도. 테두리, 모서리 블록, 번호,
  선군이 패드 어디에 인쇄되어 있는지를 정규화 좌표로 적어 둔 것이다. 실물
  패드와 다른 이름을 넣으면 엉뚱한 자리를 잰다. 실물 도안과 맞는 것은
  `legacy` 하나뿐이고, `v2` 와 `v2_protected` 는 아직 도안이 만들어지지 않았다.
- **`pad_size_px`** · `1120` — 비스듬히 찍힌 패드를 정면으로 펴서 몇 픽셀짜리
  정사각형으로 만들지. 모든 영역 좌표가 여기에 비례한다. 올리면 세밀하지만
  느려지고, 원본에 없는 해상도가 생기지는 않으므로 원본이 흐리면 소용없다.
- **`pad_size_mm`** · `null` — 패드 한 변의 실제 길이. 채우면 mm 환산이 붙는다.
  실물 치수가 확정되지 않아 비워 두었고, 비워 둬도 스코어에는 영향이 없다.
- **`detect.blur_ksize`** · `5` — 패드를 찾기 전에 사진을 얼마나 뿌옇게 만들지.
  노이즈가 뭉개져 테두리가 매끈해진다. 너무 키우면 테두리 자체가 뭉개진다.
  패드를 찾는 데만 쓴다 — 분진은 원본으로 재므로 올려도 측정값은 안 뭉개진다.
- **`detect.threshold_scales`** · `[1.0, 1.15, 1.3, 1.45]` — 흑백으로 가르는
  경계를 순서대로 시도할 배율. 화면에서 패드가 작으면 자동으로 잡히는 경계가
  패드가 아니라 배경과 바닥면 사이에 놓인다. 테두리 잉크는 순흑이 아니라
  회색이라 그 경계 바로 아래에 깔리고, 패드가 조금 밝게 찍히면 테두리 일부가
  경계를 넘어 액자 모양에 구멍이 뚫려 검출이 통째로 실패한다. 그래서 못 찾으면
  경계를 인쇄색 쪽으로 넓혀 다시 본다. 앞의 값으로 찾으면 뒤는 시도하지 않으니
  잘 찍힌 사진의 처리 시간은 그대로다.
- **`detect.local_fallback`** · `true` — 위 배율로 다 못 찾았을 때 국소 이진화로
  한 번 더 볼지. 임계 하나를 사진 전체에 쓰면 사진에서 어두운 것은 무엇이든
  인쇄색이 된다. 요철 도장면의 그늘이나 패널 이음새가 잉크로 찍히고, 거기 닿은
  테두리가 그것들과 한 덩어리가 되어 액자 모양을 잃는다. 화소마다 자기 주변
  평균과 견주면 그 결합이 끊어진다 — 벽 그늘은 주변도 같이 그늘이라 제자리에서는
  어둡지 않고, 테두리는 바로 옆이 밝은 여백이라 어느 기준으로도 어둡다.
- **`detect.local_block_ratio`** · `0.033` — 그 "주변" 으로 볼 창의 크기. 사진
  짧은 변 대비 비율이다. 테두리 두께보다 넉넉히 커야 창 안에 잉크와 여백이 함께
  들어와 대비가 생기고, 너무 키우면 전역 임계와 다를 바 없어진다.
- **`detect.local_offset`** · `25` — 주변 평균보다 이만큼 어두워야(흑색 바탕은
  밝아야) 인쇄색으로 친다. 0 에 가까우면 노이즈까지 인쇄색이 되고, 키우면 옅게
  찍힌 테두리를 놓친다.
- **`detect.local_open_steps`** · `[0, 5, 9]` — 국소 이진화 결과에서 지울 선
  굵기를 순서대로 시도한다. 0 은 지우지 않음이다. 주변과 견줘도 진짜 어두운
  선(벽 패널 이음새 등)은 남는데, 그것이 패드에 닿아 있으면 테두리와 한 덩어리가
  된다. 이음새는 가늘고 테두리는 굵으므로 굵기로 가른다. 크게 잡으면 이음새는
  확실히 끊기지만 테두리가 얇게 찍힌 사진에서는 테두리까지 갉으므로, 지우지 않는
  쪽부터 필요한 만큼만 지운다.
- **`detect.border_tolerance`** · `0.02` — 찾은 사각형이 정말 바깥 테두리인지
  확인할 때 허용할 두께 오차. 패드 한 변 대비 비율이다. 정면으로 편 이미지에서
  잉크 띠가 네 변 모두 규격 두께여야 하고, 어긋나면 안쪽 테두리로 다시 맞춘 뒤
  규격 두께만큼 밖으로 되짚는다.

  **검출이 조용히 어긋나는 것을 막는 장치다.** 패드가 벽에서 떨어져 그림자가
  지면 그림자가 잉크만큼 어두워 패드 끝과 그림자 시작을 밝기로 가를 수 없다.
  그러면 사각형은 찾아지지만 한쪽 변이 그림자 속으로 밀려, 검출은 성공으로
  보이는데 좌표계가 어긋난 채 틀린 값이 나온다. 실패로 끊기는 것보다 나쁘다.
  `null` 이면 확인하지 않는다.
- **`detect.min_pad_area_ratio` / `max_pad_area_ratio`** · `0.002` / `0.98` —
  사진 전체 넓이 대비 패드가 차지할 넓이의 하한과 상한. 사진에는 패드 말고도
  사각형처럼 생긴 것이 찍히므로 넓이로 먼저 거른다.

  하한은 곧 **패드가 최소 몇 픽셀로 찍혀야 하는가** 다. 4080×3060 사진에서
  `0.002` 는 한 변 158px, `0.005` 는 250px 에 해당한다. 높게 잡으면 멀리서
  찍힌 사진이 검출을 시작하기도 전에 잘린다 — 실촬영에서 219~230px 로 찍힌
  패드가 `0.005` 에 걸려 통째로 실패했다. 면적은 1차 거름망일 뿐이고 뒤에 링
  구조, 사각형, 채움도, 종횡비, 테두리 규격 검증이 남아 있으므로 낮춰도
  오검출로 이어지지 않는다.
- **`detect.approx_epsilon_ratio`** · `0.02` — 윤곽선을 "네모" 로 볼 때 얼마나
  대충 볼지. 올리면 구불구불한 것도 사각형으로 인정해 오검출이 늘고, 내리면
  조금만 휘어도 패드를 놓친다.
- **`detect.require_ring`** · `true` — 가운데가 뚫린 사각형만 패드로 인정할지.
  패드 테두리는 속이 빈 액자인데 현장의 사각형 물체는 대개 꽉 차 있어서, 이
  조건 하나로 오검출이 크게 준다. 테두리가 사진 밖으로 잘려 액자가 끊긴
  경우에만 끈다.
- **`detect.min_solidity`** · `0.85` — 찾은 모양이 얼마나 빈틈없이 채워져
  있어야 하는지. 반듯한 사각형은 1 에 가깝고 갈라진 모양은 작다.
- **`detect.max_aspect_ratio`** · `3.0` — 가로세로가 얼마나 찌그러진 것까지
  봐줄지. 비스듬히 찍으면 사다리꼴이 되는데, 극단적으로 눕혀 찍은 사진은
  어차피 측정 정밀도가 떨어진다.
- **`detect.edge_trim_ratio`** · `0.15` — 테두리 각 변을 잴 때 양 끝에서 버릴
  비율. 꼭짓점을 정밀하게 잡으려고 꼭짓점을 직접 보지 않고 네 변에 직선을
  맞춘 뒤 교점을 쓰는데, 인쇄된 모서리가 둥글게 뭉개져 있어 그 구간을 피한다.
  올리면 직선을 맞출 재료가 줄고, 내리면 뭉개진 모서리가 섞여 꼭짓점이 흔들린다.
- **`orient.min_margin`** · `null` — 회전 방향 판정을 얼마나 확신할 때만
  받아들일지. 패드 네 모서리 중 세 곳에만 사각형이 인쇄되어 있어 비어 있는
  곳으로 방향을 잡는데, "가장 비어 보이는 곳" 과 "그 다음" 의 차이가 이 값이다.
  방향을 잘못 잡으면 좌표계가 90도 틀어져 엉뚱한 곳을 재므로 넉넉히 걸어 둔다.
- **`quality.max_edge_rise_ratio`** · `null` — 얼마나 흐린 사진까지 받아들일지.
  밝기가 바뀌는 데 걸리는 거리가 패드 폭의 몇 배인가로 잰다. 패드 폭으로
  나누므로 촬영 거리와 무관하게 비교된다. 실촬영 표본에서 0.004 안팎이 나왔다.
- **`quality.min_tenengrad`** · `null` — 선명도를 재는 다른 방식. 클수록
  선명하다. 잉크 농도나 조명 세기에 따라 값이 같이 변하는 약점이 있어서, 둘 중
  어느 쪽이 실제 판독 실패와 잘 맞는지 보고 하나만 쓰면 된다.
- **`quality.max_saturated_bright_ratio` / `max_saturated_dark_ratio`** ·
  `null` — 밝기가 잘려나간 화소를 몇 %까지 봐줄지. 카메라는 0~255 로
  기록하므로 255 를 넘는 밝기는 전부 255 가 되어 구분이 안 된다. `0.01` 이면
  패드 면적의 1%까지 허용이다.
- **`quality.saturation_bright_level` / `saturation_dark_level`** · `null` —
  밝기 몇부터를 "잘렸다" 로 셀지. 임계가 아니라 세는 방식의 정의이며, 이 값에
  걸린 화소는 측정에서 뺀다. 둘 다 비어 있어 지금은 빼는 화소가 없다. 미리
  넣어 두면 순백에 가까운 깨끗한 여백이 통째로 빠지는 일이 생긴다.
- **`quality.min_pad_size_px`** · `null` — 사진 속 패드 한 변이 최소 몇 픽셀은
  되어야 하는지. 너무 멀리서 찍으면 아무리 보정해도 원본에 없는 정보는 안 생긴다.
- **`quality.max_pad_size_diff_ratio`** · `null` — 기준 사진과 패드 크기가
  얼마나 달라도 되는지. 크게 다르면 촬영 위치가 바뀐 것이라 비교가 성립하지
  않는다. 차이 비율은 임계와 무관하게 항상 결과에 나온다.
- **`normalize.gradient_correction`** · `true` — 옆에서 빛이 들어 생긴 밝기
  기울기를 지울지. 그대로 두면 어두운 쪽이 오염으로 오판된다. 테두리는 원래
  밝기가 어디나 같다는 것을 알고 있으니, 위치에 따라 다르게 찍혔다면 그건 순전히
  조명 탓이다. 여백 화소로 맞추지 않는 이유는 고르게 쌓인 분진까지 조명으로
  보고 지워 버리기 때문이다.
- **`normalize.ring_samples`** · `600` — 그 기울기를 잴 때 테두리에서 몇 군데를
  볼지. 최소 3점이면 되지만 그러면 어떤 값이든 완벽하게 들어맞아 결과가 맞는지
  틀린지 알 수 없다. 많이 재야 추정이 실제와 얼마나 어긋나는지가 숫자로 나온다.
- **`dust.clean_percentile`** · `90.0` — 여백의 어느 분위수를 "깨끗한 톤" 으로
  볼지. uniform 축의 기준이다. 높일수록 가장 깨끗한 일부만 기준으로 삼아
  민감해진다. localized 축처럼 주변 대비로 재지 않는 이유는, 분진이 넓게 퍼지면
  주변도 같이 어두워져 넓게 깔릴수록 값이 깎이기 때문이다.
- **`dust.local_window`** · `0.08` — 주변을 얼마나 넓게 볼지. 패드 한 변 대비
  비율이며 localized 축의 기준이다. 이 창보다 큰 덩어리는 배경으로 흡수되어
  가장자리만 잡힌다. 반대로 키우면 조명 변화까지 얼룩으로 오인한다.
- **`dust.depth_threshold`** · `0.05` — 주변보다 이만큼 어두우면 분진으로 본다.
  테두리 잉크를 1 로 놓은 척도다. 실증 전 잠정값이다.
- **`dust.min_blob_px` / `max_blobs`** · `4` / `50` — 노이즈로 버릴 덩어리
  크기와 결과에 담을 덩어리 수. 고운 분진은 낱알이 수천 개로 흩어져서, 한두
  화소까지 세면 개수가 의미를 잃고 전부 담으면 응답을 읽을 수 없다. 전체 개수는
  따로 알린다.
- **`score.uniform_reference` / `localized_reference`** · `null` — 각 축의
  스코어가 1.0 이 되는 값. 둘 다 비어 있는 지금은 원값을 그대로 0~1 로 자른다.
  현장 분포를 보고 채우면 그때부터 그 값을 1.0 으로 놓고 비례 환산한다. 두 축은
  `total = uniform + localized − uniform × localized` 로 합치며 조정 파라미터는
  두지 않는다.
- **`visualize.heat_max`** · `0.5` — 분포 이미지에서 빨강이 가리킬 값. 기준
  대비 화소 하나가 어두워진 깊이다. 고정해야 두 장을 색으로 바로 견줄 수 있다.
  비우면 사진마다 그 안의 최댓값까지 늘려 칠해서, 깨끗한 패드도 어딘가는 빨갛게
  나와 색만 보고는 심한지 알 수 없다. 넘는 화소는 빨강으로 잘리며, 잘렸는지는
  이미지 캡션의 실제 최댓값으로 알 수 있다.
- **`target_id.enabled` / `digits`** · `true` / `null` — 패드에 인쇄된 관측
  포인트 번호를 읽을지와 몇 자리인지. 학습 모델이 아니라 같은 모양의 숫자를 다시
  그려 겹쳐 보는 방식이다. 못 읽어도 판독 실패가 아니다 — 패드는 읽혔고 분진
  스코어는 유효하다. 자릿수가 전부 같다면 넣어 두는 편이 안전하다. 얼룩을 숫자로
  착각해 한 자리 더 읽는 사고를 막는다.
- **`target_id.font_dir`** · `../assets/fonts` — 숫자 템플릿을 그릴 폰트를 찾을
  폴더. 그리는 폰트가 인쇄에 쓴 폰트와 다르면 닮은 정도가 떨어져 자리를 잘못
  읽는다. 실제 인쇄 폰트(TTF/OTF)를 넣어 두면 그것을 쓰고 비어 있으면 내장
  폰트로 돈다. 상대 경로는 설정 파일이 있는 폴더 기준이고, `/config` 에는 푼
  결과가 절대 경로로 나온다. 여러 개면 이름 순 첫 번째만 쓴다.
- **`lines.enabled`** · `true` — 지금은 쓰이지 않는다. 패드 하단의 굵기가 다른
  선 4개를 재는 실증용 지표를 위해 남겨 둔 자리이며, 현재 파이프라인은 이 값을
  보지 않는다. 켜도 꺼도 판독 결과가 달라지지 않는다.
- **`service.host` / `port`** · `0.0.0.0` / `8911` — 판독 결과에는 영향이 없고
  바꾸려면 재시작해야 한다. 컨테이너에서는 `host` 가 `0.0.0.0` 이어야 하고,
  `port` 만 바꿔서는 바깥에서 접속되지 않으므로 `docker-compose.yml` 의 포트
  연결도 함께 맞춘다.

## 임계값을 처음 정하는 순서

1. 임계값을 전부 `null` 로 둔 채 현장 사진을 최대한 많이 판독한다
2. 결과에서 각 측정값의 분포를 본다
3. 눈으로 "이건 못 쓰겠다" 싶은 사진을 몇 장 골라, 그 사진들의 측정값이 정상
   사진과 어디서 갈라지는지 찾는다
4. 그 경계를 임계값으로 넣고 다시 돌려, 의도한 사진만 걸러지는지 확인한다

한 번에 여러 임계값을 넣지 않는 것이 요령이다. 무엇 때문에 걸렸는지 알 수 없게
된다. 판독 불가일 때는 어느 항목에서 걸렸는지가 결과에 함께 나온다.
